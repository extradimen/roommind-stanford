# G5全新场景家族评分验证协议

日期：2026-09-12。状态：本地草案，尚未生成对话、外发或启动研究。

## 目的

验证维度隔离评分契约能否在未参与提示设计的材料上稳定工作。该验证只评估评分协议，不能证明
RoomMind架构效果，也不能替代后续2×2组件因果研究。

## 防止开发集泄漏

- 旧谈判、市场发布、候选人面试、事故响应及其世界版本全部视为开发家族。
- G1–G4.15所有转录、v1–v4预测、Codex单一专家标签和新语义复评均不得进入新场景内容、
  标签模板或评分提示。
- 新家族在任何对话生成前登记名称、角色类型、事实结构、程序结构、停止规则和哈希。
- 冻结后不得按评分结果替换家族、删案例或修改标签定义。

## 拟议的新家族框架

1. 公共图书馆馆藏空间分配：馆长、无障碍顾问、青少年项目负责人、档案员。
2. 研究联盟数据发布审查：首席研究员、隐私负责人、复现审查员、合作机构代表。
3. 博物馆借展与保护决策：策展人、保护科学家、保险代表、借展方协调员。
4. 社区交通班次调整：调度负责人、乘客权益代表、司机代表、预算分析员。

这些家族不得复用旧家族的专名、数字、日期、义务图或逐句模板。每个家族至少冻结两个独立世界
实例；样本单位是家族，不把同一对话的六个评分当作六个独立样本。

## 评分与参考顺序

1. 冻结场景、角色、共同世界、条件分配和模型绑定。
2. 生成并封存转录，保存原始事件、回执和哈希。
3. 生成只含盲化材料的参考包；评分器不得看到条件。
4. 先冻结独立参考判断，再运行固定评分器；禁止根据评分器输出修改参考。
5. 技术失败仅补算缺失维度，已完成结果和转录哈希不得覆盖。
6. 报告逐维一致、混淆、弃权、技术失败和条件猜测；不使用单一总体分数掩盖退步。

评分器验证与架构效应筛查分开：第一阶段每个世界只生成一条对话，A/B/C/D各分配两条，共8条；
这个小组只产生48个“场景×维度”开发判断，条件不是参考标签，也不估计架构效应。评分门通过后，
第二阶段才建立每世界四臂完整区组，共32条对话，用于候选选择；它仍不是正式确认研究。

若仍由Codex单一专家提供参考，必须继续标为AI开发诊断，不能称为人类准确率。正式确认门仍需
独立人类参考、预声明阈值和未用于开发的新一批家族。
