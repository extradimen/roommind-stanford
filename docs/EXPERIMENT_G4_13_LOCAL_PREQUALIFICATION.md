# G4.13 Required Response and Terminal State Convergence

G4.13 is a narrow exploratory successor to G4.12. It addresses only failures
observed in the frozen G4.12 qualification batch; it does not change the study
scenarios, model, seed policy, evaluation rubric, or Baseline implementation.

## Frozen motivating evidence

- Runs 532, 534, and 536 violated the ordered player-addressed response lock:
  a named role could become silent after output rejection, allowing another
  role or the autonomous player to consume that role's floor.
- Run 534 published a rejected polite confirmation ("I'm pleased to confirm")
  and later opened another player/NPC floor after the apparent terminal point.
- Run 536 let the autonomous player claim that results were currently stored
  in a dashboard without a simulated-tool result.
- Run 538 also violated direct same-turn NPC response routing.

## Mechanisms under test

1. Every explicitly addressed participant receives an ordered response slot,
   including ordered multi-addressee questions.
2. If the normal renderer cannot safely publish that response, a role-aware
   deterministic response is subjected to the same publication checks and is
   used only for the required response owner.
3. Same-turn NPC-to-NPC response owners receive the same required-response
   guarantee; unresolved ownership remains queued rather than being relayed by
   the player.
4. A task already terminal at the autonomous-step boundary locks the floor
   before another player move is generated.
5. Rejected lifecycle transitions include polite confirmation constructions,
   and current-world claims generated by the player remain subject to the same
   evidence boundary in retrospective scenarios.

## Local prequalification gates

- all server smoke tests pass;
- client and admin production builds pass;
- required-response fallback is safe, non-empty, and role-local;
- player-addressed targets retain public order and cannot be overtaken;
- direct NPC response scheduling remains bounded;
- the exact G4.12 polite rejected-confirmation wording is rejected;
- the exact G4.12 unsupported dashboard claim is rejected;
- a pre-existing terminal task state generates no additional player or NPC
  speech;
- no dialogue code, model binding, scenario, or research artifact changes
  after the G4.13 manifest is frozen.

## Live qualification gates

- deployed revision and frozen manifest match the authorized G4.13 commit;
- 8/8 dialogues freeze with zero dialogue failures and no degraded fallback;
- all transcript hashes recompute exactly before and after evaluation;
- all G4.13 and applicable legacy probes pass on every RoomMind run;
- no post-terminal speech, player relay, unsupported current-world claim, or
  required-response ordering violation appears in manual pair review;
- independent six-dimension evaluation completes for all 48 run-dimensions;
- the four RoomMind/Baseline pairs are manually reviewed before disposition.

G4.13 remains exploratory. Passing local and live gates does not authorize
external human review or support a confirmatory claim.
