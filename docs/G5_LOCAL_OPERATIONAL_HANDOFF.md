# G5 本地运行与交接检查

范围：离线工程交接，不是服务上线、真实模型实验、科学资格或全部研究门通过。
现有旧运行器、模型配置、冻结批次及研究数据不迁移、不覆盖。本文件不授权任何外部动作。

## 当前运行入口

1. 冻结 factorial manifest、分析计划、抽样目标、校准要求和家族登记；
   `study_preflight` 检查完整原始证据。synthetic_control 与真实研究必须分开。
2. 用 `OfflineAssembler` 重建明确注册的离线组件；每个场景显式提供世界、角色卡及停止规则。
   调用者注册的传输仍属可信代码，不是沙箱。不能把 provider 字符串当网络隔离证明。
3. 将工厂交给 `LocalBatch`，使用固定的持久控制库和世界库。所有分配先验证才创建世界。
   同配对四组的重开请求表必须一致，预算内版本、稳定ID和目标episode冻结。
4. 单个消费者迭代 `run()`；退出时关闭生成器后关闭batch。不能带着旧worker另开一份控制库。
   所有世界冻结且源重验成功后才取 `evaluation_inputs()`，它不会启动评价。
5. 独立评价使用冻结计划/控制格及追加归档。已完成或N/A不覆盖；技术失败留痕，只补缺项。
   用 `release.verify_evidence` 或对应控制面板检查完整来源与评价，不以局部格代替完整面板。

## 恢复规则

| 情况 | 本地处理 | 禁止推断/动作 |
|---|---|---|
| 消费者中断 | 先确认原消费者退出，原控制库/世界库/manifest重新打开 | 新建替代批次，重置预算/历史 |
| 生成提交确认丢失 | 从权威事件/请求日志恢复同请求结果 | 无条件重放用户动作 |
| 技术异常 | 保留attempt，恢复同冻结配置；检查错误来源 | 将语义拒绝、正常终止当技术失败无限重试 |
| 预测远程结果不确定 | 原worker停止后显式处理pending_indeterminate | 宣称远端推理exactly-once |
| 竞争者/配置漂移/换库 | 拒绝并调查 | 绕过合作锁、复制控制库来强行运行 |
| 源或历史摘要改变 | 停止使用旧交接证据，另存审计结果 | 重新哈希后声称旧证据没有变化 |

锁是合作式本机Unix机制，不是跨主机租约。文件副本、直接数据库写入、非合作worker不在
保证范围。测试模拟进程退出/事务回滚，不宣称已测试真实数据库服务整体崩溃。

## 可执行检查

从本仓库根目录，用已有本地Python运行。输出必须是不存在的新路径；旧失败/成功回执均保留。

```bash

PYTHONPATH=server .venv312/bin/python -m app.g5.local_handoff --receipt docs/G5_LOCAL_ACCEPTANCE_NEW.json --output docs/G5_LOCAL_HANDOFF_NEW.json
PYTHONPATH=server .venv312/bin/python -m app.g5.local_handoff --verify docs/G5_LOCAL_HANDOFF_NEW.json
git diff --check
```

第一条仅在明确的本机测试数据库执行。后三条不访问数据库或模型。
交接检查要求验收含PostgreSQL、没有失败/错误/跳过、测试会计完整、回执内容摘要正确，
并核对当前**全部**G5 Python实现和测试文件集合（新增源码也会使旧回执失效）。
递归记录research/experiments中的普通文件摘要，验证时新增、删除或变化均报告不一致；
符号链接拒绝。它是交接时点库存，不证明以前没有丢过文件，也不证明家族语义独立。
当前未覆盖非G5生产服务、Python依赖供应链、部署配置和服务器认证，不能把它当部署包签名。

摘要无签名。可信操作者能重造回执，恶意并发写入也不受快照锁防护；它只提供本地一致性
证据。正式发布还须独立审查、依赖与环境锁定、版本认证及授权。历史工件更新后应保留旧
交接包，另建新包，不能覆盖旧包或用新快照倒推旧时点完整性。
