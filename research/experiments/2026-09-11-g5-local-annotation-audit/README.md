# G5 独立标注/裁决审计合成工件

`panel.json` 保存4份完整源工件、冻结标注计划、全部56条原始记录和重放报告。
24个案例覆盖4份源×6维；2名声明的合成标注者分别提交48条记录，8个预先设置的分歧
由第3个合成身份裁决为uncertain。16例原标签一致；分歧历史仍在，未被裁决覆盖。
无真人标注、外部模型调用或真实校准结论。所有身份来源均为synthetic。

工件内容摘要（去掉自身sha256后的canonical JSON）：
`cd38859e0ff00235ed89c6551c73adfd98cbb607012422c3ce909526ba77a910`。

`annotation_archive.verify_export(panel['archive'])` 重建独立SQLite内存归档，验证源工件、
任务/引文、原始标签引用及完整记录链，重算报告。记录哈希不是身份签名。

使用边界：

- task只含待评文本、共同上下文、维度/rubric和中性案例ID，不给独立标注者其他标签；
  adjudication_task只在全部独立标签到齐且有分歧时提供原始记录及所需引用摘要。
- 缺一个标注者仍为awaiting_annotations；全员分歧而未裁决为disputed；不按多数静默
  决定，不用缺失标签自动补clear。uncertain/N-A可为已处理，但绝不是通过。
- 原始同意标签分别导出并保留各自来源；一个案例可能有多个label record，科学单位
  仍为案例，不可把这些记录当独立样本。裁决来源不伪装成所有原标注者一致。
- 空转录只接受uncertain/N-A和明确空引文；旧freeze_labels要求非空引文，不能输出的
  条目在legacy_export_omissions单列，原记录和案例分母不删除，不放宽旧协议。
- 人类kind/不同ID仅是来源声明，代码不能证明是真人、彼此独立或未私下看过其他标签。
  中性ID和正文中潜在身份泄漏仍需实际盲评流程审查。

定向验证涵盖损坏/错引文/错身份/重复改写拒绝、重连、无关DB保护、事务内真实子进程
退出回滚、提交后确认丢失恢复。新归档独立于世界库，未改生产库、Postgres模型或旧工件。
