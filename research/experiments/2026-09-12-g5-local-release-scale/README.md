## 仍存在的规模与恢复限制

1. `freeze_results` 每次仍重验全部参考；参考归档逐条重放又验证已有记录，案例增长并非
   常数成本。`verify_export` 逐事件重建预测库还有重复全量工作。本包没有伪造线性扩展结论。
2. 当前恢复 API 仅限单worker；没有所有权租约、fencing token或旧进程自动停止的证明。
   SQLite事务避免两个started同时成功，但不能阻止调用者错误地对活跃worker显式恢复。
3. `resume_pending` 现在严格要求布尔值。默认不重推未确定调用；显式true仍要求先确认旧
   worker停下，不能保证外部推理恰好一次。已持久完成的结果不会重做，弃权也是完成。
4. 不应直接把这个私有参考入口挂到无人值守多worker在线API。可靠单实例执行入口、
   活跃所有权与恢复防重入应作为下一个完整本地工作包，并先用脚本传输/真实子进程验证。
